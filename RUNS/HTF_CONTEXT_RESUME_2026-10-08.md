# HTF Context Engine — резюме: что сделано и как (08.10.2026)

Задание: по ТЗ «HTF Context Engine» построить для каждого LTF-сигнала бота **причинную
карту старших ТФ на момент решения** (4H/1D/1W: FVG, свинги, PDH/PDL/PWH/PWL, dealing range,
карта пути к цели) и собрать исследовательский датасет. Без LLM, без торговых решений,
без подбора порогов — только слой данных + форма зависимости.

## 2. Ключевые решения семантики (и почему так)

- **decision_time = scan = конфирм-бар + 15 мин** (момент постановки лимитки). Всё считается
  по барам с `close_time <= decision_time`; незакрытая HTF-свеча не участвует.
- **FVG доступен после close третьей свечи; свинг — после close правой** (как в старом
  `scan_sol_htf_liquidity_flow_v2.py` и в ТЗ §3/§4).
- **Дистанция до FVG — до границы ОСТАТОЧНОЙ (незаполненной) части зоны**, а не полной зоны:
  `FVG_BULL: [lo, min_low_since]`, `FVG_BEAR: [max_high_since, hi]`. Если остаток целиком
  «за спиной» — не препятствие. (Причина: полная зона давала ложные «0.0R» — огромные старые
  зоны накрывали entry, хотя их незаполненная часть была уже позади.)
- **Состояния:** FVG ACTIVE/PARTIALLY_FILLED/FILLED; свинг ACTIVE/SWEPT/BROKEN. Пройденное
  (FILLED / SWEPT / BROKEN) — не препятствие (ТЗ §5).
- **§6 (source-уровень):** `htf_sweep_level` исключается из препятствий строгим матчингом
  (2 bps, только 4H) — по уровню свинга или границе FVG-зоны. Широкий матчинг «зона содержит
  уровень» был отвергнут: он вырезал десятки старых зон и искажал карту (проверено на смоуке ADA).
- **Кап карты 5R** (в 6-й корзине >3R объектов ≥3R в карте столько, сколько влезло в 5R;
  сигналов без объектов в 5R — ровно 1).
- Карта пер-ТФ (`fvg_above/below`, `swing_above/below`) — НЕ фильтруется по направлению и НЕ
  фильтруется exclusion (это описательный слой); path/summary — фильтруются.

## 3. Результат первого этапа (§17 ТЗ)

**Монотонной зависимости «чем больше room_R — тем лучше» НЕТ.** Есть устойчивый **бинарный
разрыв**: сделки, у которых ближайшее препятствие < 0.25R, дают ноль/минус, а «есть место» —
устойчиво плюс.

| группа | n | tp/sl/time | WR | ΣR | avgR | CI95(t) | недельный t |
|---|---|---|---|---|---|---|---|
| <0.25R (вплотную) | 346 | 132/117/97 | 38.2% | +2.7 | **+0.008** | [−0.085, 0.101] | **−0.05** |
| &nbsp;&nbsp;=0.0 (вход в остатке зоны) | 74 | 25/31/18 | 33.8% | −7.3 | **−0.099** | [−0.304, 0.107] | — |
| &nbsp;&nbsp;(0, 0.25) | 272 | 107/86/79 | 39.3% | +10.0 | +0.037 | [−0.068, 0.141] | — |
| ≥0.25R | 651 | 330/198/123 | 50.7% | +109.6 | **+0.168** | [0.099, 0.238] | **+3.61** |

По годам (avgR): <0.25R — 2024 +0.101 / 2025 −0.081 / 2026 −0.054; ≥0.25R — +0.131 / +0.208 / +0.157.
По ногам: <0.25R — LONG −0.006 / SHORT +0.026; ≥0.25R — LONG +0.140 / SHORT +0.197.
По терцилям стопа «плохая» группа пустая во всех трёх (не артефакт ширины стопа).
Состав <0.25R: в основном свежие ACTIVE-объекты (FVG 208, свинги 70, PDH/PDL/PWH/PWL 68);
почти-заполненных (fill ≥ 0.9) всего 6 — это не «огрызки», а реально близкие уровни.

Дополнительно: признаки internal (FVG) и external (свинги+PDH/PWH) дают ту же форму
(<0.25R — худшая корзина); ближайшее препятствие на **4H** — лучший разрез (+0.152, CI [0.087, 0.217]),
на 1W — нулевой (−0.008). `tp_blocked` (room<1R) не разделяет.

**Честные оговорки:** это in-sample 2024–2026 (окно калибровки кандидата); порог не
утверждается и никуда не встраивается (ТЗ §16); busy-механика движка означает, что эффект
фильтра нельзя считать как «выкинуть группу» — для этого нужен отдельный прогон с фильтром
и портфельный сим (следующий этап, если решите продолжать). TON с 06.2026 «мёртвый» (данные
не обновляются). Кап дистанций в 5R.

## 4. Как запускать

Интерпретатор — только `D:/PYTHON/CISDBOT/.venv/Scripts/python.exe`, cwd = `D:\PYTHON\cisdbotbybit`.

```powershell
# валидация (тесты §15 + инвариантность)
python -m HTF_CONTEXT.htf_validate
#   → RUNS/cache/htf_context_validation.json

# пересборка датасета + отчёта (сигналы берутся из RUNS/temp/live_tf_htfctx/rows_tf1v2/)
python -m HTF_CONTEXT.research_htf_context
#   → RUNS/cache/htf_context.jsonl, htf_context_summary.csv, RUNS/HTF_CONTEXT_REPORT_2026-10-08.md

# только отчёт по готовому JSONL (быстро, без пересборки)
python -m HTF_CONTEXT.research_htf_context --skip-build

# глазной просмотр одного сигнала
python -m HTF_CONTEXT.show_context --symbol SOL --scan "2024-01-07 03:00"
```

Перепрогон сигналов (если нужен другой конфиг): править `MODES` в `RUNS/temp/htfctx_run.py`
(остальное как в `stop_timing_run.py`), запуск через `bash RUNS/temp/boot_htfctx.sh`
(или очистить `live_tf_htfctx/rows_tf1v2/*.pkl` и перезапустить).
