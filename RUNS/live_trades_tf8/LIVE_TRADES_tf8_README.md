## Логика стратегии (чтобы не восстанавливать по коду)

- Основной ТФ **30m**, старший **8H** (`htf_ratio=480` минут), активен только tf8.
- Сетап: **свип экстремума 8H-свечи** + структура CISD. Подтверждение — **30m-свеча закрывается ЗА уровнем CISD**
  (не касание: детектор требует close-rejection, см. `detectors/cisd_htf.py`, `find_first_sweep_close_confirm_bar`).
- После подтверждения выставляется **лимитка на уровне CISD**, живёт 30 минут (`limit_h=0.5`), затем снимается.
- Стоп — по структуре базы, **тейк = 1R** (`_tp_1r`), позиция держится **6 часов**, затем закрытие по времени.
- Комиссии Bybit: maker 0.036%, taker 0.10% (учтены в поле `fees`).

## Подводные камни (важно для того, кто анализирует)

1. **`shadow_trades.json` НЕ полная история.** Там 32 закрытые сделки, а `shadow_positions.json` содержит 80 записей
   (включая 8 аннулированных `voided_invalid_setup` от 16.09 и сделки до 16.09) и журнал — 80 `entry_filled`.
   Если нужен полный список — берите positions/journal, а не trades.
2. **Скрипт-пропуски.** В журнале **289 `signal_skipped`** — сигналы, которые бот не взял (причины внутри событий).
   Это отдельный, ещё не изученный слой данных.
3. **Класс «фитиль» сюда не попадает.** Требование закрытия 30m за уровнем отсекает сетапы, где уровень
   только проткнут фитилём. На более ранней выгрузке (16–18.09) этот класс дал 7 убыточных сделок из 7.
4. **Не сравнивать с бэктестом напрямую.** До 19.09.2026 движок бэктеста имел 25-минутный look-ahead
   (филл считался от ОТКРЫТИЯ конфирм-бара +5 мин вместо закрытия). Исправлено: `_fill_from_after_confirm_close`.
   Кэши до этой правки (`RUNS/filters_off_full/`) содержат ошибку; честные — `..._full_aligned/`.
5. **Аномально узкие стопы** были проблемой на MEXC-версии бота; здесь средний стоп 1.295%, но отдельных
   выбросов стоит проверить (`stop_price` против `cisd_level`).
