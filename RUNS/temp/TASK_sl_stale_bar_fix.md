# Задание кодеру: ложные закрытия позиций в SHADOW (paper) по «прошлому» бару

**Файл:** `D:\PYTHON\cisdbotbybit\cisdbot.py` (Bybit-бот; MEXC-версию `D:\PYTHON\CISDBOT` НЕ трогать)
**База:** md5 `342427cadd8975105f8f6c75dfa9052f` (совпадает с сервером `/opt/cisdbotbybit/cisdbot.py`)
**Тип правки:** только ветка PAPER/SHADOW. LIVE-логику (ордера на бирже) не менять.

---

## 1. Проблема (факт, воспроизведено)

Сделка ADA/USDT, 16.09.2026: вход 0.1946 в 02:43:53 UTC, «СТОП ЛОСС» в 02:44:00 UTC (через 7 секунд).
По 1m-данным Bybit цена после входа не опускалась ниже 0.1937 — стоп 0.1921 не был тронут. Закрытие ложное.

Причина: в PAPER-ветке монитора позиций проверка стопа/тейка берёт экстремум из
`state.ohlcv_closed[f"{symbol}|{tf}"]` — это **последний закрытый бар ТФ**, без привязки ко времени входа.
На момент входа там лежал 30m-бар 02:00–02:30 (закрылся в 02:30, ДО создания лимитки), у которого
low = 0.1921 — ровно уровень стопа (стоп ставится за экстремум свипа, который проторгован раньше входа).
Монитор увидел `bar_low <= stop` и закрыл позицию мгновенно.

Тот же класс бага уже исправлен для ФИЛЛА: гейт `_shadow_ohlc_usable_for_fill` (стр. 11610) + поле
`pl.closed_bar_at` (стр. 785/827/870, заполняется на 9693, применяется на 10885).
У позиции (`Position`) аналога нет — её OHLC-ветка смотрит в кэш без гейта.

## 2. Что именно ломается (зачем правим)

- Ложный стоп = лишний минус; ложный тейк = фиктивная прибыль. Оба искажают paper-баланс и `/stats`.
- Найденные фантомы: ADA 16.09 (ложный SL), BNB 14.09 09:59:36 (ложный TP, +1.02 / net +0.68),
  ETH 15.09 00:10:19 (закрыт по стопу через 1.7 с, реально стоп пробит через ~6.5 мин). 3 из 39 закрытых.
- LIVE не затронут (там стоп-ордер на бирже), но именно SHADOW-статистика используется для сверки live с бэктестом.

## 3. Как править

### 3.1 Новые поля позиции
`Position.__init__` (стр. 897–940), рядом с `confirm_bar_time` (940):
- `self.closed_bar_at: str = ""` — open-time последнего закрытого бара ТФ на момент ОТКРЫТИЯ позиции;
- `self.px_min_since_entry: float = 0.0` и `self.px_max_since_entry: float = 0.0` — экстремумы live-цены с момента входа.

Провести через сериализацию, как соседние поля:
- `to_dict` (мета-блок 956–987) — добавить три поля (по образцу `sig_hash`, стр. ~981);
- `from_dict` (мета-блок 1002–1031) — восстановить их (`""` / `0.0` для старых записей).

Семантика времён — **naive UTC**, как везде в боте. Сравнения — через существующий `_bar_time_to_utc`
(он снимает tz через `.replace(tzinfo=None)`, без конверсии). Не подсовывать tz-aware строки.

### 3.2 Заполнение при открытии позиции
Место рождения позиции в paper-филле: стр. 10916–10927 (сразу после `pos = Position(...)` / перед
`state.positions.append(pos)`). Переменная `cached` уже в скоупе (используется на 10885):
- `pos.closed_bar_at = str((cached or {}).get("time") or "")`
- `pos.px_min_since_entry = pos.px_max_since_entry = float(avg_price)`

### 3.3 Гейт + экстремумы с момента входа в мониторе
PAPER-ветка `position_monitor()`, стр. 11202–11221.

1. Рядом с получением live-цены (стр. 11194 `price = get_price(...)`) обновлять экстремумы:
   при `price is not None` — `px_min_since_entry = min(..., price)`, `px_max_since_entry = max(..., price)`.
2. Новый хелпер по образцу `_shadow_ohlc_usable_for_fill` (11610) — например
   `_shadow_ohlc_usable_for_position(p, cached)`: возвращает True только если бар кэша **целиком после входа**:
   `bar_t > max(closed_bar_at, entry_time)`; при отсутствии данных — `False` (консервативно: OHLC-ветка выключена).
3. Проверки закрытия считать по трём источникам — live-цена, экстремумы с момента входа и бар кэша (только при `True` из хелпера):
   - LONG: `sl_hit = price <= stop or px_min_since_entry <= stop or (bar_ok and bar_low <= stop)`;
   - LONG: `tp_hit = price >= tp  or px_max_since_entry >= tp  or (bar_ok and bar_high >= tp)`;
   - SHORT — зеркально.
4. Приоритет исходов оставить как есть: сначала TP, затем SL, затем таймаут. Таймаут (`now >= p.exit_time`) не трогать.

Почему так: `bar_t >= entry_time` (бар целиком после входа) закрывает дыру полностью — экстремум бара,
начавшегося до входа, не может «сработать» стопом. Плату за это (SL/TP внутри бара входа) компенсируют
10-секундные live-поллы через `px_*_since_entry`.

### 3.4 Наблюдаемость (обязательно)
В запись журнала `closed` (`trade_logs/trades_YYYY-MM.jsonl`) и в `Position.to_dict` добавить:
- `exit_src`: `"live_px"` / `"since_entry"` / `"bar"` — по какому источнику сработало закрытие;
- `exit_bar_time`: `time` бара кэша, если закрытие по бару (иначе `None`).

Это чтобы следующий такой разбор не требовал раскопок по логам.

## 5. Критерии приёмки

1. `python -m py_compile cisdbot.py` — чисто.
2. Юнит-проверка на синтетике (скриптом, положить в `RUNS/temp/`), без сети:
   - позиция LONG entry=100 stop=99, `entry_time` = 10:05:00, `closed_bar_at` = "…10:00:00";
     кэш бара `{time:"…10:00:00", low:98.5}` → SL **не** срабатывает (это сегодняшний кейс);
   - кэш бара `{time:"…10:30:00", low:98.5}` → SL срабатывает;
   - `px_min_since_entry = 98.9` (при живой цене 100.5) → SL срабатывает;
   - позиция без поля `closed_bar_at` (старая запись) → OHLC-ветка выключена, ложного SL нет.
3. На сервере после деплоя+рестарта: в `trade_logs/*.jsonl` за сутки нет `closed_sl`/`closed_tp`
   с `exit_time − entry_time` меньше 2 минут (проверять `RUNS/temp/audit_sl_stale2.py`).
4. Прогон аудита на 39 исторических сделках: новых ложных закрытий нет; три старых фантома
   (`Lecdf997a` ADA, `L76de05b5` BNB, `L066f9814` ETH) остаются в истории как есть — их НЕ перезаписывать.
5. В `closed`-записи видны `exit_src` и `exit_bar_time`.

## 6. Деплой (после проверки кода)

1. Локально: `python -m py_compile cisdbot.py`, `git show HEAD --stat` (что затронуто), прочитать дифф целиком.
2. Архив только с нужными файлами: `tar czf deployN.tar.gz cisdbot.py` (если правка не задела `backtest/*.py` — больше ничего не нужно).
3. На сервере бэкап точки отката: `cp cisdbot.py cisdbot.py.bak_<короткий_хеш>`.
4. Деплой: `scp` → `tar xzf` в `/opt/cisdbotbybit` → `md5sum` локально и на сервере (должны совпасть) → `sudo systemctl restart cisdbotbybit`.
5. После рестарта: свежие сканы в `bot.log` без новых Traceback; открытые позиции, восстановленные из
   `shadow_positions.json`, пойдут по консервативному пути (`closed_bar_at` пустой → только live-цена) — это ожидаемо.
