# ИНЦИДЕНТ: live_tf_grid.py — OUT_DIR терялся в spawn-воркерах (ночь 28.09.2026)

## Суть бага
В `live_tf_grid.py` глобальный `OUT_DIR` устанавливался только в `main()`.
На Windows multiprocessing использует **spawn**: воркеры стартуют как новые
интерпретаторы и `main()` в них НЕ выполняется → `OUT_DIR=""` → `run_symbol()`
писал все файлы в **общий корень `live_tf/`** вместо `live_tf/{mode}/`.

## Что произошло (факты по логам)
- В корень писали ПЯТЬ прогонов: `tf8`, `tf7e13_002`, `tf1`, `tf2`, `tf7e8_002`.
- Смешение: у пары (sym, year) файл от того, кто записал ПОСЛЕДНИМ (os.replace, гонка).
- **tf2** завершился за 5 минут, «проскипав» чужие файлы (skip по существованию):
  его единственная запись — LTC_2026 (n=30). Результат tf2 в корне — фикция.
- **tf1** завершился (EXIT=0), успев перезаписать часть 2025-х файлов.
- **tf8** завершился, его 2026-е (KAS 39 / ADA 46 / LINK 49) — в корне (частично перезаписаны).
- **tf7e13_002** и **tf7e8_002** были живы на момент разбора (считали LTC 2026).
- Числа не сходятся с конфигами (напр. KAS_2024: tf7e13 n=118, tf8 n=94 — кто победил
  в файле, видно по n; LTC_2024 n=52 (tf1) и т.п.) — корень НЕВАЛИДЕН.
